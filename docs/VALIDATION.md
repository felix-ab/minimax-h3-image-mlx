# Validation

Every number on this page is regenerated by `parity/summarize.py` from saved dumps. The reference is PyTorch running
diffusers' and transformers' own MiniMax-H3-Image / Qwen3-VL modules, streamed one block at a time. A harness
check (`ref/check_harness.py`, `ref/check_te_harness.py`) shows this is bit-identical to the stock forward passes.
"rel" is ||a − b|| / ||b||. "Truth" is the float32 reference on CPU.

## Float32: is it the same computation?

| stage | MLX vs PyTorch |
|---|---|
| initial noise (`torch.randn`, CPU generator) | bit-identical |
| canvas, rotary grid, sigma round trip, patchify, velocity step | bit-identical (21 cases) |
| text encoder, hidden_states after 19 layers | rel 4.15e-07 |
| transformer, 50 blocks, velocity, steps 0 and 4 | rel 5.27e-06, 5.14e-06 |
| VAE decode (tiled) / encode (tiled) | max abs 1.5e-5 / rel 1.1e-6 |
| text-to-image end to end, 512×384, latent after 6 steps | rel 2.81e-05 (image 73.8 dB) |
| edit end to end, 512×512, one reference | image 55.4 dB, SSIM 0.9996 |

## bf16: is it as good as PyTorch?

bf16 inference of this 33B model is chaotic: residual-stream differences of a few ulps grow to ~2% in the
velocity per step. So the right question is how MLX compares with PyTorch's own bf16 backends, run from the same
inputs. MLX GEMMs are bit-identical to PyTorch-MPS at every model shape; normalisation, modulation, SwiGLU and
RoPE are bit-identical or within 0.001%; SDPA equals float32 attention rounded once.

| distance to float32 truth | PyTorch-CPU | PyTorch-MPS | MLX |
|---|---|---|---|
| transformer velocity, step 0 | 2.25e-02 | 1.96e-02 | 2.16e-02 |
| transformer velocity, step 4 | 2.41e-02 | 2.49e-02 | 2.80e-02 |
| text encoder, 50 layers | 1.10e-02 | 1.10e-02 | 1.10e-02 |
